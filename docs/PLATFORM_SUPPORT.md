# Platform support

This page separates what has been verified from what is only configured. A platform is listed as supported only when its build and test path is documented and has run.

CI verification means the workflow ran on GitHub-hosted runners. It does not prove behavior on every machine of that OS. Cgo builds depend on the local C toolchain, and those variations are not tested.

Go versions: the `test` jobs use the version that `setup-go` resolves for `go.mod` (`go 1.27.3`). Each job has a "Record Go toolchain" step. Earlier releases contain reachable standard-library vulnerabilities; see [SECURITY.md](SECURITY.md#vulnerability-scanning).

## Build requirements per OS

| OS | Requirements | Build command |
|---|---|---|
| Linux | Go 1.27.3, `gcc` | `go build -trimpath -o bin/argus-asm ./cmd/argus-asm` |
| macOS | Go 1.27.3, Xcode Command Line Tools | Same as Linux |
| Windows | Go 1.27.3, MinGW-w64 GCC on `PATH` | `go build -trimpath -o bin\argus-asm.exe .\cmd\argus-asm` |

## Platform-specific behavior

| Topic | Linux | macOS | Windows |
|---|---|---|---|
| Default database | `$XDG_CONFIG_HOME` or `~/.config`, then `argus-asm/argus-asm.db` | `~/Library/Application Support/argus-asm/argus-asm.db` | `%AppData%\argus-asm\argus-asm.db` |
| File modes | `0600` file, `0700` new directory | Same as Linux | The tool requests the same modes, but Windows does not apply Unix mode bits. Access follows the folder's ACLs, so keep the database in a folder only your account can read |
| Path handling | Absolute path via `filepath.Abs` | Same | Same; drive letters and backslashes are accepted |
| Standard input `-` | Supported | Supported | Supported; use PowerShell `Get-Content` to pipe |
| Signals | SIGINT and SIGTERM cancel the context | Same | SIGINT (Ctrl+C) cancels the context; SIGTERM is not generated by Windows, so it is only relevant to programmatic termination |
| Line endings | LF and CRLF accepted in CSV | Same | Same |

## Not verified yet

- Architectures other than amd64 on Linux and Windows, and arm64 on any platform.
- A local Windows or macOS run. Their results come from GitHub-hosted runners only.

- Behavior of cgo builds with unusual toolchains, such as Alpine/musl, is not documented or tested.
- Behavior on network-mounted home directories (for example NFS or SMB) with SQLite WAL is not tested. Prefer a local disk for the database.
- Packaging for each OS (installers, Homebrew, Scoop, system packages) does not exist. The `release-artifacts` CI job builds an archive and a SHA-256 file on each runner, and `make dist` does the same on a Unix host. Nothing is published, and the artifact jobs are verified only when CI runs them.
